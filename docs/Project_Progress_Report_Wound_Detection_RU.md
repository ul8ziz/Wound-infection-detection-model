# Обнаружение и сегментация послеоперационных ран — Отчёт о ходе работы

---

## 0. Введение

Данный проект разрабатывает конвейер глубокого обучения для обнаружения и сегментации послеоперационных ран на клинических фотографиях в рамках магистерской диссертации по анализу раневой инфекции.

**Были проведены два основных эксперимента** на подготовленном наборе данных (380 изображений, 532 аннотации ран):

| Эксперимент | Архитектура | Подход |
|-------------|------------|--------|
| **Эксперимент 1** | Mask R-CNN (ResNet-50-FPN) | Одноэтапная сегментация экземпляров |
| **Эксперимент 2** | YOLO11m-seg + U-Net++ | Двухэтапный: детекция, затем уточнение ROI |

**Лучшие результаты (тестовая выборка):**

| Метрика | Mask R-CNN | YOLO11m-seg (отдельно) | Комбинированный конвейер (настроенный) |
|---------|----------:|----------------------:|--------------------------------------:|
| bbox AP50 | 0.398 | **0.817** | 0.750 |
| bbox AP75 | 0.063 | — | **0.522** |
| segm AP50 | 0.217 | **0.662** | 0.561 |
| Dice | — | — | 0.670 |

Конвейер YOLO11m-seg + U-Net++ превзошёл Mask R-CNN по всем метрикам. Цикл оптимизации комбинированного конвейера улучшил точность bbox при IoU 0.75 в **42 раза** (с 0.012 до 0.522).

## 1. Проблемы и решения

### 1.1 Проблемы набора данных

| Проблема | Влияние | Решение |
|----------|---------|---------|
| **Несогласованные имена файлов** в 241 папке задач CVAT | Невозможно надёжно объединить данные | Построен конвейер стандартизации: `task_{id}_img_{global}_{label}.jpg` с полной CSV-таблицей маппинга |
| **Отсутствие явных меток инфекции** | Необходимы для задачи классификации | Выведены из эвристики имён файлов (`-not-` = не инфицирован); исключены 150 неоднозначных случаев |
| **Слабое качество аннотаций** для детализированных классов (отёк, некроз, фибрин и др.) | Мультиклассовая сегментация была ненадёжной | Область исследования сужена до сегментации **только ран** — единственного класса с согласованными аннотациями |
| **Малый набор данных** (369 изображений с ранами) | Риск переобучения | Применена офлайн-аугментация 4x (→ ~1028 обучающих изображений) + онлайн медицинская аугментация |

### 1.2 Технические проблемы

| Проблема | Влияние | Решение |
|----------|---------|---------|
| **Несоответствие ROI padding** — U-Net++ обучалась с `roi_padding=0.12`, но на инференсе использовалось 0.10 | Сдвиг распределения: ухудшение качества масок | Выровнено до 0.12 везде |
| **Режим ограничивающей рамки** — `padded_roi` генерировал рамки из расширенной ROI-вырезки, а не из маски | Слишком свободные bbox → `bbox_AP75 = 0.012` | Переключено на `mask_tight`: bbox вычисляется из контура предсказанной маски |
| **Дыры и шум в масках** U-Net++ | Снижение Dice/IoU и плохое визуальное качество | Добавлена морфологическая постобработка `close_fill` |
| **Пропуск обнаружений** при высоком пороге уверенности | Некоторые раны получали оценку 0.2–0.5, пропускались при conf=0.5 | Комбинированный конвейер использует двухэтапную фильтрацию: YOLO при conf=0.001, затем Python-фильтр при 0.20 |
| **Оценка исключала пропущенные изображения** — Dice до оптимизации вычислялся на 51/55 изображений | Метрики были завышены | Исправлена оценка: учитываются все 55 изображений (пропущенное = Dice 0) |

### 1.3 Итоговое влияние

После решения этих проблем комбинированный конвейер достиг:
- `bbox_AP75`: 0.012 → **0.522** (улучшение в 42 раза)
- `segm_AP75`: 0.042 → **0.099** (улучшение в 2.3 раза)
- Пропущенных изображений: 4 → **1**

## 2. Используемые технологии

### 2.1 Выбор архитектур

| Технология | Роль | Обоснование выбора |
|------------|------|-------------------|
| **Mask R-CNN** (ResNet-50-FPN) | Эксперимент 1: базовая модель | Промышленный стандарт сегментации экземпляров; хорошо документирована; обеспечивает надёжную базу для сравнения |
| **YOLO11m-seg** | Эксперимент 2, Этап 1: детекция + грубая сегментация | Современный детектор реального времени со встроенной головой сегментации; значительно быстрее и точнее Mask R-CNN для локализации ран |
| **U-Net++** (EfficientNet-B1) | Эксперимент 2, Этап 2: уточнение масок | U-образная архитектура превосходна для точной сегментации границ; работает на вырезанных ROI для более высокого эффективного разрешения; кодировщик EfficientNet обеспечивает сильные признаки при умеренном размере |

### 2.2 Почему двухэтапный конвейер

Одна модель должна балансировать между локализацией раны на полном изображении и созданием точных пиксельных границ. Двухэтапная архитектура разделяет эти задачи:

1. **YOLO11m-seg** обрабатывает полное изображение (768px) для обнаружения области раны — оптимизирован для локализации.
2. **U-Net++** обрабатывает только вырезанную ROI раны (384×384) — оптимизирована для точности границ.

Такое разделение позволяет каждой модели сосредоточиться на своей сильной стороне.

### 2.3 Вспомогательные технологии

| Технология | Назначение |
|------------|-----------|
| **PyTorch** | Фреймворк глубокого обучения |
| **Ultralytics** | Обучение и инференс YOLO11m-seg |
| **Segmentation Models PyTorch (SMP)** | Реализация U-Net++ |
| **Albumentations** | Медицински безопасная аугментация (сохраняет геометрию маркера) |
| **COCO API (pycocotools)** | Стандартизированная оценка AP |
| **Focal-Dice Loss** | Лучше справляется с дисбалансом классов (рана vs фон), чем BCE |
| **CosineAnnealingLR** | Плавное затухание скорости обучения для U-Net++ |
| **Морфологическая постобработка** | Заполнение дыр, сглаживание границ масок |

## 3. Сравнение экспериментов

### 3.1 Сравнение конфигураций

| Параметр | Mask R-CNN | YOLO11m-seg + U-Net++ |
|----------|----------:|----------------------:|
| Модель детекции | Mask R-CNN (ResNet-50-FPN) | YOLO11m-seg |
| Модель уточнения | — | U-Net++ (EfficientNet-B1) |
| Размер входа (детекция) | 512 × 512 | 768 |
| Размер входа (уточнение) | — | 384 × 384 |
| Размер батча | 2 | 4 (YOLO) / 8 (U-Net++) |
| Эпохи | 50 | 60 (YOLO) / 50 (U-Net++) |
| Оптимизатор | SGD (lr=0.001) | SGD (YOLO) / AdamW (U-Net++) |
| Функция потерь | стандартная | стандартная (YOLO) / focal-dice (U-Net++) |
| Время обучения | ~53 мин | ~67 мин + ~28 мин = ~95 мин |
| Общее число параметров | ~44M | ~20M + ~8M = ~28M |

### 3.2 Сравнение метрик на тестовой выборке

| Метрика | Mask R-CNN | YOLO (отдельно) | Комбинированный (настроенный) | Лучший |
|---------|----------:|----------------:|-----------------------------:|--------|
| bbox AP | 0.152 | — | **0.481** | Комб. |
| bbox AP50 | 0.398 | **0.817** | 0.750 | YOLO |
| bbox AP75 | 0.063 | — | **0.522** | Комб. |
| segm AP | 0.058 | — | **0.198** | Комб. |
| segm AP50 | 0.217 | **0.662** | 0.561 | YOLO |
| segm AP75 | 0.008 | — | **0.099** | Комб. |
| combined AP50 | 0.308 | 0.739 | **0.656** | YOLO |
| Dice | — | — | **0.670** | Комб. |
| IoU | — | — | **0.549** | Комб. |

### 3.3 Ключевые выводы

1. **YOLO11m-seg более чем удвоил результат Mask R-CNN** — bbox AP50 вырос с 0.398 до 0.817 (+105%).
2. **Сегментация утроилась** — segm AP50 с 0.217 до 0.662 (+205%).
3. **Комбинированный конвейер добавил точность при высоком IoU** — bbox AP75 = 0.522 — сильнейший показатель в проекте (Mask R-CNN достиг лишь 0.063).
4. **Главная слабость Mask R-CNN:** низкое разрешение (512px) и отсутствие этапа уточнения привели к плохому качеству границ (`segm_AP75 = 0.008`).
5. **Остаточная слабость комбинированного конвейера:** `segm_AP75 = 0.099` по-прежнему низкий, в основном из-за ошибок выравнивания ROI-маска в 33% тестовых изображений.

## 4. Подробные результаты экспериментов

### 4.1 Эксперимент 1: Mask R-CNN

**Архитектура:** Mask R-CNN, ResNet-50-FPN, `num_classes=2` (фон + рана).
**Вход:** 512 × 512, размер батча 2, 50 эпох, SGD lr=0.001, умеренная медицинская аугментация.
**Лучшая эпоха валидации:** 13 (`combined_AP50 = 0.417`).

**Результаты на тестовой выборке:**

| Метрика | Значение |
|---------|--------:|
| bbox_AP50 | 0.398 |
| bbox_AP75 | 0.063 |
| segm_AP50 | 0.217 |
| segm_AP75 | 0.008 |
| combined_AP50 | 0.308 |
| Время обучения | 3207 с (~53 мин) |

Эта модель послужила функциональной базой. Она подтвердила работоспособность набора данных и конвейера от начала до конца, но низкие метрики сегментации подтвердили необходимость более сильной архитектуры.

### 4.2 Эксперимент 2: YOLO11m-seg + U-Net++

**Вход:** 768px, батч 4, 60 эпох, SGD, офлайн-аугментация 4x (~1028 изображений).

| Метрика | Валидация | Тест |

| bbox precision | 0.897 | — |
| bbox recall | 0.820 | — |
| bbox mAP50 | 0.859 | **0.817** |
| bbox mAP50-95 | 0.516 | **0.539** |
| segm mAP50 | 0.718 | **0.662** |
| segm mAP50-95 | 0.260 | **0.250** |

#### Этап 2 — U-Net++ (уточнение масок ROI)

**Вход:** ROI-вырезки 384 × 384, EfficientNet-B1, AdamW, focal-dice loss, 50 эпох.

| coco_segm_AP75 | 0.042 | **0.099** | ×2.3 |
| combined_AP50 | 0.589 | **0.656** | +11% |
| mean_dice | 0.708 | **0.670** | скоррект. оценка |
| Оценено изображений | 51/55 | **54/55** | +3 восстановлены |

### 5.8 Анализ ошибок

Анализ ошибок был проведён на всех 55 тестовых изображениях. Каждое изображение категоризировано по доминирующему типу ошибки. Подробные отчёты доступны в `experiments/YOLO11m_UNetPP/results/combined/error_analysis/error_report_test.md`. Главный вывод: **смещение ROI или маски** составляет 33% тестовых изображений, что делает его приоритетной целью для улучшения через более точное выравнивание координат ROI-маска.
